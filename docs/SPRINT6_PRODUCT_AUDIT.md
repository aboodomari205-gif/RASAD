## Implemented behavior and regression protection

Historical comparison errors now appear at the historical controls. Matching, pinned sensitivity, candidate trace and the Research Brief no longer depend on valid unrelated period inputs. The historical text brief, clipboard copy and complete evidence JSON remain disabled while their requested comparison is invalid. The separate scientific-comparison export does not include that user-entered historical comparison and remains usable when its matching inputs are valid.

Starting/restarting the guide restores valid observed-year periods, default 1 km / 60 min matching and its pinned reference, along with the existing full Ajloun scope reset. This preserves the story: problem → actual observations → provisional associations → sensitivity → evidence limits → research verification.

The added production-browser regression deliberately creates the invalid historical interval, asserts that matching still shows five pairs, confirms Research Brief is enabled and historical JSON is disabled, then starts the guide and verifies the error clears. Existing deterministic scientific/export tests were retained unchanged.

## Measured local performance

Fresh Chrome profiles, local static server, desktop headless Chromium with software WebGL permitted. These are single-run observations, not a statistically controlled benchmark or a public-network/mobile-device result.

| Measurement | Before | After |
| --- | ---: | ---: |
| DOMContentLoaded end | 460.0 ms | 329.4 ms |
| First contentful paint | 496 ms | 468 ms |
| Median route-check elapsed | 521.7 ms | 519.9 ms |
| Maximum route-check elapsed | 534.6 ms | 540.4 ms |
| Routes retaining original MapLibre canvas | 18/18 | 18/18 |

Route-check elapsed includes a fixed **400 ms** settling delay, browser-protocol overhead and UI navigation. It is not pure route-render latency. First contentful paint is not “Earth fully interactive” or map-tile completion. Resource collection spans assets loaded during the test, not only the first viewport. Worker timing entries can be inconsistent across execution contexts and were not used for performance conclusions.

Largest observed uncompressed assets: FireMap approximately **1.10 MB**, EarthScene **924 KB**, bundled MapLibre worker **519 KB**, entry bundle **464 KB**. Vite's large-chunk advisory remains. Map and Earth code are already split by the existing architecture. No broad performance optimization was applied, and the timing differences above are **not claimed as an optimization gain**. Separating validation also prevents period edits from rerunning the matching memo, as a consequence of the correctness fix; no quantified render-speed claim is made.

## Remaining limitations and prioritized recommendations

1. **Scientific verification dependency:** obtain acquisition/swath/cloud/quality evidence, independent event truth and reviewed comparable baselines before stronger coverage, event or anomaly claims. Current detections do not establish verified zero activity or confirmed fires.
2. **Provenance dependency:** independently verify original deliveries and supply archive checksums. Their absence remains visible in Research Brief; no checksum was fabricated.
3. **P2 performance follow-up:** benchmark on physical low-end mobile hardware and a throttled network before considering further Earth/MapLibre chunk work. Single local measurements do not prove competition-venue performance.
4. **P2 UX follow-up:** consolidate redundant brief navigation and consider a shorter mobile path to deep evidence disclosures. Preserve explicit scientific caveats and keyboard access.
5. **Acceptance boundary:** testing used local Chromium and current archive snapshots, not Safari/Firefox, a public deployment, field validation or NASA endorsement. External basemap services still require network access.
